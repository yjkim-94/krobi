# CLI Image Generation Integration — Design Spec

**Date:** 2026-06-17  
**Status:** Draft  
**Branch:** spec/pet-evolution-pipeline

## Problem

The current add-pet workflow requires manual steps between prompt generation and asset ingestion:
1. Copy prompt from Claude → open ChatGPT web → paste → download image → drop into `_incoming/`

This interrupts the flow and makes the pipeline hard to repeat. The goal is to call image generation directly from the terminal so the entire pipeline stays in one session.

## Chosen Approach

Wrap [`chatgpt-imagegen`](https://github.com/leeguooooo/chatgpt-imagegen) (ChatGPT OAuth, no API key required) in a thin project script `tools/gen_image.py`. The wrapper is the only place that knows about the backend; everything else (add-pet skill, build_form.py) stays unchanged.

Backend switching to the OpenAI API later is a flag change only — no call-site changes.

## Architecture

```
add-pet skill
  └─ generates prompt → saves to tools/prompts/<species>_<form>.txt
       └─ prints: python tools/gen_image.py tools/prompts/... --out src/assets/pets/_incoming/...
            └─ tools/gen_image.py
                 ├─ backend=oauth (default): chatgpt-imagegen → gpt-image-2
                 └─ backend=api  (future):   openai SDK      → gpt-image-2
                      └─ saves PNG to _incoming/<species>_<form>_sheet.png
```

## Components

### `tools/gen_image.py` (new)

```
usage: gen_image.py <prompt_file> --out <path> [--size WxH] [--backend oauth|api] [--ref <image>]
```

| Argument | Default | Notes |
|---|---|---|
| `prompt_file` | required | Path to `.txt` file with the full prompt |
| `--out` | required | Output path, e.g. `src/assets/pets/_incoming/krombi_stage2-maker_sheet.png` |
| `--size` | `1536x1024` | Landscape for 4×8 sheet layout |
| `--backend` | `oauth` | `oauth` = chatgpt-imagegen; `api` = OPENAI_API_KEY |
| `--ref` | none | Reference image path (forwarded to backend if supported) |

**Backend abstraction:**

```python
def generate(prompt: str, size: str, ref: str | None, backend: str) -> bytes:
    if backend == "oauth":
        return _chatgpt_oauth(prompt, size)        # chatgpt-imagegen subprocess call
    elif backend == "api":
        return _openai_api(prompt, size, ref)      # openai SDK, supports ref images
```

- OAuth backend calls `chatgpt-imagegen` as a subprocess (it handles auth/session).
- API backend uses `openai` SDK directly; supports `--ref` via image edit endpoint.
- Output is always written to `--out` path.

### `tools/prompts/` (new directory)

Stores the text prompt files generated by add-pet skill. Each file is named `<species>_<form>.txt`. Files are gitignored (ephemeral, per-session artifacts).

### add-pet skill change

Step 3 currently ends with "copy this prompt and paste into Nano Banana."  
After this change, Step 3 ends with:

1. Save the prompt to `tools/prompts/<species>_<form>.txt`
2. Print the ready-to-run command:
   ```
   tools/venv/bin/python tools/gen_image.py \
     tools/prompts/<species>_<form>.txt \
     --out src/assets/pets/_incoming/<species>_<form>_sheet.png
   ```
3. Tell the user to run it, then come back when the image appears in `_incoming/`.

The Step 4 gate (inspect preview) and Step 5 onward are unchanged.

### Dependency installation

`chatgpt-imagegen` is installed into the existing `tools/venv`:

```bash
tools/venv/bin/pip install chatgpt-imagegen
```

No new venv needed. `openai` SDK is added at the same time (zero cost now, needed for the API backend later).

## Constraints & Known Limits

**Reference image (--ref) with OAuth backend:**  
`chatgpt-imagegen` is text-to-image only — it does not forward a reference image to the model. For stage2/3, style consistency must rely entirely on the prompt text (palette lock, creature description). The `--ref` flag is accepted by `gen_image.py` but silently ignored when `--backend oauth`. When switching to `--backend api`, the ref image is forwarded via the edit endpoint and becomes active.

**Image quality vs. web ChatGPT:**  
The OAuth CLI may produce slightly different quality than the ChatGPT web canvas interface. The existing `build_form.py` extraction + palette-cleanup pipeline remains the quality gate.

**Free plan limits:**  
Free ChatGPT accounts have lower image generation limits than Plus. If the user hits the daily cap, the script exits with a clear error; the workflow falls back to manual (same as today).

## Future: API backend migration

To switch to the API backend:

1. Set `OPENAI_API_KEY` in the environment.
2. Add `--backend api` to the `gen_image.py` call (or make it the default in `gen_image.py` when the key is detected).
3. `--ref` now works and stage2/3 get reference image consistency automatically.

No changes to add-pet skill or build_form.py.
